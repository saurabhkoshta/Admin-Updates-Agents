Admin Updates Agent

A Copilot Studio reference agent for Microsoft 365 and Azure administrators. It correlates tenant communications, public release information, and Microsoft Learn documentation, then turns the evidence into concise, source-attributed operational guidance. It also delivers a filtered weekly admin digest to Teams and email.

01 Architecture

Administrators chat with the agent interactively. A weekly recurrence flow invokes the same agent to produce digests. All tools run with invoker (user) authentication, and each MCP server has one distinct evidence role.

Tenant evidence Public release evidence Documentation evidence Subscription state Digest delivery Scheduled trigger

02 Evidence model

Each source has one authority. The agent never uses a source outside its role, keeps each source's IDs, dates, and links, and shows conflicts instead of silently reconciling them.

Tenant

MCP Server for Enterprise

  • Proves whether and how this tenant is affected
  • Message Center posts: category, tags, major change, services
  • Service Health incidents and advisories
  • Read-only: never acknowledges or remediates items
Public

Release Communication Server

  • Proves what is changing publicly and when
  • Microsoft 365 Roadmap items and Azure Updates
  • Roadmap IDs, release status, rollout timing
  • Does not prove tenant availability
Documentation

Microsoft Learn Docs MCP Server

  • Proves documented behavior and procedures
  • Prerequisites, limitations, known issues, remediation
  • Availability labels (preview / GA) update product state
  • Does not rewrite roadmap dates or prove tenant impact

Past-due roadmap reclassification

When a roadmap date is earlier than today, the original status is kept as history. The agent searches Enterprise and Learn again and assigns one current state from the newest evidence:

UpcomingA current source gives a future date
Rolling outMessage Center or docs say rollout is in progress
PreviewLearn explicitly says preview
Generally availableLearn explicitly says GA
Delayed or cancelledRoadmap or Message Center says so
Status unresolvedSupporting searches are inconclusive

03 How it works

  1. Administrator
    Asks about a Message Center post, incident, roadmap item, Azure update, or product behavior.
  2. Orchestrator
    Infers intent from product names, IDs, dates, and keywords, then interprets relative dates against the current date in the instructions.
  3. Routing
    Tenant → Enterprise. Public → Release Communication. "How / why / fix" → Learn. If ambiguous, it searches both Enterprise and Release instead of asking.
  4. Grounding
    Answers only from tool results and keeps IDs, dates, status, and links. No match means "no matches found" for the stated topic and date range, not "nothing exists".
  5. Response
    Direct answer first. Results are grouped by source, and agent guidance is labeled separately from Microsoft-stated actions.
  1. Primary source
    Queries the source that matches the main evidence need: public change, tenant impact, or documented behavior.
  2. Anchors
    Extracts exact product and feature names, Message Center IDs, roadmap IDs, error codes, and versions for follow-up searches.
  3. Supporting sources
    Adds a source only when it fills a distinct evidence role. Past-due roadmap items always trigger Enterprise and Learn checks.
  4. Correlation
    Labels each relationship Confirmed, Likely related, or Possible supporting information. It never merges records.
  5. Briefing
    Primary finding → supporting evidence → tenant relevance → documentation → known issues → guidance (Microsoft-stated / suggested / needs validation).
  1. Lookup
    Every review, update, test, or disable request starts with an owner-scoped Get admin digest subscriptions.
  2. Validate
    Requires at least one supported product and one delivery method, plus Teams team and channel or valid email recipients.
  3. Confirm
    Summarizes the values or changes and waits for explicit confirmation before any write.
  4. Write
    Creates or updates only the caller's row, changing only the fields they asked for. Disable sets Active = No and keeps history.
  5. Test
    Runs weekly-admin-digest for that profile only, labels it a test, and reports each delivery separately.
  1. Trigger
    Daily-MC-Trigger runs weekly and invokes the agent with the scheduled time as the digest end time.
  2. Subscriptions
    Loads active, due rows and processes each one independently so one failure doesn't block the others.
  3. Collect
    Queries Message Center for the rolling 7-day window in the subscription's time zone.
  4. Filter
    Product ∈ selected products AND category ∈ {planForChange, preventOrFixIssue} AND tag = Admin impact. Missing values never match.
  5. Organize
    Deduplicates by post ID, groups by category → major change (Yes first), and sorts by action or rollout date.
  6. Enrich
    Adds Microsoft Learn guidance only for clearly matching posts that lack actionable detail.
  7. Deliver
    Posts an Adaptive Card 1.4 to the stored Teams channel and/or sends the email. Sends a no-result digest when nothing qualifies.
  8. Record
    Writes Last Delivery At and Last Delivery Status. Partial failures are reported per channel.

05 Security and trust boundaries

ID
Identity

Integrated (Entra ID) authentication is always required, and access is limited by group membership.

INV
Invoker connections

Every tool runs as the signed-in user, so connector permissions define the reachable data.

DV
Row ownership

Subscriptions are user-owned. The agent never accepts a user-supplied row ID and uses only IDs from the owner-scoped lookup.

TX
Delivery scope

Teams and email go only to destinations stored on the subscription being processed. Success is reported only after the action succeeds.

RO
Read-only tenant access

The agent never claims to acknowledge, dismiss, or remediate a tenant item.

PII
No leakage

Never exposes credentials, connection details, internal identifiers, or raw tool payloads. The package ships sanitized placeholders.

08 Known gaps and next steps

Scheduling

Per-subscription schedule isn't honored

The flow runs once a week (Monday 08:00 Central), so the stored day, time, and time zone only shape the reporting window. An hourly trigger that selects due rows would honor each schedule.

Determinism

Filtering is model-driven

Category, tag, and product filters are applied by the model. Filtering in the flow before summarizing would make results reproducible.

Authorization

Owner scope is set by prompts

The Dataverse $filter is written by the model. Fix it in a flow or topic (_ownerid_value eq User().Id) and rely on Dataverse roles.

Delivery

Email and Teams tools are general-purpose

Recipients and channels are limited only by instructions. Consider moving delivery into the flow, or allowlisting tenant domains.

Quality

No evaluation set

Add a Copilot Studio test set that covers the SETUP.md scenarios, and run it before each release.

ALM

Flow and table are ZIP-only

Unpack the solution into source (pac solution unpack) and add CI that packs, checks, and hashes the ZIP.
