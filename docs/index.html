01 / architecture

Ask in chat. Follow the evidence.

The agent routes the request to the sources that can answer it. Supporting searches add evidence, not assumed tenant impact.

What applies to this tenant?

Message Center posts and Service Health incidents establish tenant-specific findings. Keep the returned IDs, dates, status, affected services, and links. No returned match means the search found no match, not proof that no issue exists.

What is changing publicly?

Roadmap items and Azure Updates describe public changes and release timing. They do not prove tenant availability. Past-dated roadmap items need current supporting evidence before being labelled upcoming or available.

What does Microsoft document?

Learn supplies documented behavior, prerequisites, limitations, known issues, and procedures. A documentation page is not evidence of an active tenant incident. Keep Microsoft-stated guidance distinct from the agent's suggestions.

02 / in chat

Choose the scope in your question.

No enrollment step. No product list to maintain. Conversation context helps follow-up questions, but there are no saved subscription preferences.

A product briefing

"What changed for Microsoft Teams in the last seven days?"

Retrieve relevant evidence for that product and state the exact reporting period.

All products

"Show admin-impact updates across all products this week."

Do not restrict the product scope. Explain source coverage, paging limitations, and unavailable sources.

Tenant relevance

"Is this roadmap feature rolling out to our tenant?"

Correlate public information with tenant evidence. Do not infer tenant impact from the public roadmap alone.

Technical guidance

"What are the prerequisites and known issues for this change?"

Find clearly matching official documentation and link to the source.

On demand, not scheduled. The agent can write a briefing here in chat. It cannot subscribe you, save a schedule, email a digest, or post it to a Teams channel later.

05 / boundaries

What this simplification does and does not change.

Shared connections require restricted agent access

The agent requires Microsoft sign-in and uses centrally managed Agent author authentication for all three MCP tools. Approved administrators can chat without Copilot Studio editing access or individual tool connections. They share the Enterprise service account's data access, not their individual tenant permissions. Restrict use to an approved administrator security group, keep credentials in an approved vault, and retain MFA and Conditional Access. Review actual connector and MCP permissions; research-only instructions do not reduce an overly broad permission grant.

No custom subscription table is not the same as no Dataverse platform dependency

The subscription data model is removed. Copilot Studio and its Power Platform environment still have their normal licensing and platform requirements.

An old unmanaged installation is not automatically cleaned up

Importing a smaller unmanaged package does not remove components already installed by the old digest solution. Turn off old scheduled flows, back up data, and review dependencies before removing old tables, roles, environment variables, or unused connections. See the migration guidance.

Briefings are evidence-based, not a guarantee of exhaustive coverage

The agent can only use the records the sources return. Responses should state the reporting period, unavailable sources, and retrieval limitations. Public roadmap information alone never establishes tenant impact.
